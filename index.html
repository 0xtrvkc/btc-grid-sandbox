How this backtest works

SIMPLE SPOT GRID / V1

01 · Range & initialization

N grid levels include both endpoints, so there are N − 1 intervals. Arithmetic: Lᵢ = bottom + i × (top − bottom)/(N − 1). Geometric: Lᵢ = bottom × (top/bottom)^(i/(N − 1)).

The central / trigger reference is always (top + bottom)/2, including geometric spacing. Trading starts at the first observed close inside the range; it does not wait for the exact midpoint.

Start with all fiat, then buy 50% of initial balance as BTC notional at activation, with the entry fee paid from remaining fiat. Every grid order has fixed BTC quantity initial_balance / N / activation_close. No leverage or shorting.

Following the bot’s initial filters, buys start on levels at/below center and strictly below the activation close; sells start above both center and the activation close. A level equal to activation is not filled retroactively.

02 · Orders & available funds

A filled buy places its same-size sell exactly one level up; a filled sell places its buy one level down. Each initial order is an independent cycle, so different cycles can later share a price. No rebalancing or compounding of quantity.

Resting buys reserve their full cash cost including fees; resting sells reserve BTC. Newly paired orders have funding priority, then other waiting orders nearest to the current price. An unfunded order cannot fill; it waits for funds and a subsequent crossing. These skipped crossings are reported.

Downward close moves fill crossed buys from highest to lowest; upward moves fill sells from lowest to highest. Arriving exactly on a level counts once. The previous close is excluded, the new close included. No trades are inferred for a flat bar.

Fees are quantity × execution_price × fee_rate in USD on every fill, including the seed buy and liquidation. Partial fills, exchange lot-size rules and slippage are not modeled.

03 · Risk exits & valuation

TP and SL are absolute BTC price thresholds in USD, as in the bot config. After that bar’s crossed grid orders, TP triggers at close ≥ TP and SL at close ≤ SL. All pending orders are canceled and all BTC is sold at the observed close, with a fee. A breached threshold at activation closes immediately.

After an exit, the strategy stays in fiat until the selected end, preserving the same comparison window as buy & hold. If never activated, the portfolio stays in cash. At ordinary end-of-test, remaining BTC is marked at the last close and not forcibly sold.

Running trade-log P&L is marked at each execution price; equity charts mark at each close. Realized P&L uses weighted average cost including buy fees and net sell proceeds. Total P&L includes both realized and unrealized inventory.

04 · Close-only data

Data loads directly from the three BTC dashboard JSON files. Naive timestamps are interpreted as UTC. Records are sorted, and nonpositive / invalid observations are excluded and counted. Picker limits come from each loaded file.

A close-to-close path is an approximation. It misses within-bar round trips and assumes fills at each crossed limit price. Missing intervals are not fabricated: crossings over gaps still use the two observed endpoints, and gaps are reported. Ratios assume the nominal interval.

Charts may reduce line points while preserving bucket extrema for display; every original selected bar and every fill is used for statistics. The chart-window selector changes only the visible charts.

Default dates use the last year. The default grid uses ±20% around the first selected close, never future highs/lows. Internet access is needed for data and the two chart libraries. No exchange connection or backend.

05 · Metric definitions

MetricCalculation / convention
ROI / edge100 × (final fiat + final BTC × last close − initial balance) / initial balance. Edge is grid ROI minus gross buy & hold return, in percentage points.
Buy & hold100 × (last close / first selected close − 1), without fees, matching the analyzer’s price-return benchmark. Equity line starts with the same initial capital.
Drawdown / runupLargest percentage decline from a prior running equity peak / rise from a prior running trough. Include pre-entry capital in the initial peak/trough. Underwater is the signed, negative drawdown series.
SharpePer-bar return r = Eₜ/Eₜ₋₁ − 1; excess x = r − 0.03/A. Sharpe = mean(x) / sample_SD(x) × √A. A = 365, 2,190 or 8,760 for 1D, 4H or 1H. Sample SD uses n − 1.
SortinoMatches the bot’s convention: mean(x) / sample_SD(x where x < 0) × √A. This is conditional downside sample deviation, not downside RMS. If downside SD is undefined or ≤ 1e−9, use mean(x) × √A; if Sharpe SD is undefined or ≤ 1e−9, use 0. Fewer than two closes gives N/A.
Fee / ratio timingROI, balances and drawdown include the seed fee. Ratios use consecutive observed close-equities; a seed fee already in the very first observation is not a separate return interval. Cash after an early exit earns 0%.

06 · Reference & deliberate scope

Inspired by grid_trading_bot concepts, config, performance analyzer and plotter (reviewed 14 September 2026). The current upstream implementation uses a different geometric center and its simple-grid sell search can choose the next available sell level. This sandbox follows the requested arithmetic midpoint and exactly adjacent pairing, and fixes order size from original capital. It is not a byte-for-byte reproduction of upstream backtests. Hedged grid is outside this v1.

Visual tokens and window chrome follow the sibling BTC dashboard. Charts: Chart.js 4.4.1 (cdnjs) + annotation 3.0.1 (jsDelivr). Run JSON includes the config shape, dataset coverage and a SHA-256 digest of the selected observations when available, plus results for reproducibility.
