06 / METHODOLOGY

Every number has a definition.

Financial accounting, execution assumptions and reference sources.

Binance-style construction

The default mode follows the Binance spot-grid guide: N intervals create N + 1 boundary prices, with equal dollar or proportional steps. The initial layout has one order per interval; lower boundaries below the entry close receive buys, remaining intervals receive sells at their upper boundary. This leaves one vacant price level. Filled orders reverse at the adjacent boundary.

Optional entry triggers and sell-on-stop controls are supported. Stops follow the guide’s range constraints. This implementation caps static grids at 170; it does not emulate the exchange’s dynamic order mechanism.

Capital & fee assumptions

For activation price P, seed sell count S, pending buy prices L and cash buffer b, automatic order quantity is Q = B(1−b) / [(ΣL + SP)(1+f)]. Alternatively, fixed-quantity mode uses the entered fractional BTC amount and rejects a layout that cannot be initially funded. Seed BTC is S×Q.

All fills charge USD fees. Binance may charge base currency or BNB and replenish fee reserves; that asset-conversion process, exchange rounding and minimum sizes are not simulated.

Triggers, exits & boundaries

Without an entry trigger, initialize on the first observation in range. An optional exact entry price replaces the seed execution price while preserving that timestamp; it must remain inside the grid. An exact final exit price replaces only the end-of-test liquidation price.

Crossed grid buys execute high to low and sells low to high. Stops cancel orders; sell-on-stop either liquidates or retains BTC. Retained BTC continues to affect portfolio equity after the bot stops.

Execution fidelity & local data

Close-only is the conservative default and cannot see reversals inside a bar. OHLC estimated accepts timestamped open/high/low/close objects and applies O→L→H→C to up bars or O→H→L→C to down bars. This exposes possible intrabar crossings but the true tick sequence is unknowable. 1M imported uses local minute observations and is the preferred reconstruction when exchange fills are unavailable.

The calibrated multiplier changes only the displayed grid-profit sensitivity. It never changes fills, equity, ROI or drawdown. Optional exchange grid profit and cycle count calculate error and fill capture without feeding those actual outcomes back into the simulation.

Two consistent P&L views

Grid attribution: total P&L = net matched grid profit + floating / other P&L. Match each grid buy only to the next adjacent sell in the same cycle; subtract both fees. Seed buys and stop liquidations are not matched grid pairs. The residual includes those unmatched effects and open inventory. Do not interpret it as pure unrealized profit.

Inventory accounting: total P&L = realized WAC P&L + unrealized WAC P&L. Weighted average cost includes entry fees. These are alternative decompositions, not amounts to add together. The waterfall uses gross matched spread, residual gross price effects and all fees exactly once.

Returns & annualization

Binance’s parameter reference distinguishes matched-pair grid profit and total account profit, and annualizes profit linearly using elapsed bot time. This page shows both the bot’s lifetime and the entire selected evaluation window.

MetricDefinition
Total ROI(Ending equity / initial capital − 1) × 100. Equity includes all fees and BTC marked at the latest close. No deposits or withdrawals.
Total APRROI × 365 / full-window elapsed days. Bot APR instead uses P&L at stop and days since activation. Grid APR uses matched profit / initial capital over that same bot duration.
CAGR[(Ending equity / initial capital)^(365 / elapsed days) − 1] × 100. For less than a year, this is an extrapolated annualized growth rate. It describes the actual starting and ending balances, without assuming fixed order sizes compounded.
APY scenario[(1 + Total APR/100/365)^365 − 1] × 100. Assumes the same average daily simple return is reinvested every day. This is hypothetical, not the simulated return or an earnings forecast. No annualized rate is shown for zero duration; numerical overflow is N/A.
Profit / grid[Upper boundary × (1−f) − lower boundary × (1+f)] / lower boundary × 100. Range across intervals for arithmetic; constant for geometric. This is a return on buy notional, not total portfolio capital.
Grid ROI / APRNet profit from completed adjacent buy→sell cycles divided by starting capital. Grid APR scales that realized ratio by 365 / bot lifetime days. Open inventory and unmatched price effects are excluded.
Grid APY scenarioDaily compounding of Grid APR: [(1 + Grid APR/100/365)^365 − 1] × 100. The fixed-quantity simulation does not perform this reinvestment, so APY is a comparison scenario rather than simulated earnings.
Cash-flow run rateNet matched grid profit / bot lifetime days. The normalized 30-day figure multiplies that observed daily pace by 30.4375. Pair velocity is completed matched pairs / bot lifetime days. These are historical normalizations, not forecasts.
Gross retentionNet matched grid profit / gross matched spread. Fee share is matched-pair fees / gross matched spread. They measure how much captured spread survived fees.
Capital paybackStarting capital / positive observed daily grid cash flow. This holds the historical pace constant and ignores regime change, compounding, inventory losses and downtime; N/A when cash flow is not positive.
BenchmarkBuy & hold invests all starting capital in BTC at the first selected close. Gross return is price-only. The fee-adjusted comparison pays an entry fee and, when the selected end policy liquidates, an exit fee. Both span the full evaluation window.

Risk & quant statistics

MetricDefinition
Daily sampleLast observed close-equity in each UTC day. Returns use adjacent calendar days; missing-day pairs are excluded from daily statistics, not forward-filled. The initial partial day is not a return observation. Monthly attribution starts at initial capital and includes every fee; incomplete edge months are marked.
Sharpe / SortinoDaily excess x = equity return − annual risk-free rate / 365. Sharpe = mean(x) / sample SD(x) × √365. Sortino uses √mean(min(x,0)²) over all daily observations. Undefined denominators show N/A. The scorecard also retains the original bot’s per-bar metrics with its 3% risk-free rate and conditional downside-SD convention.
DrawdownEquity decline from its preceding peak, including initial capital. Duration starts at that peak and ends at recovery or the last sample. Current recovery requirement = previous peak / current equity − 1. Runup uses the running equity trough.
Ulcer / CalmarUlcer is time-weighted RMS percentage drawdown. Calmar = CAGR / maximum percentage drawdown. Recovery factor = net P&L / maximum cash drawdown. Time below peak and BTC exposure use elapsed-time weights between observed bars.
VaR / expected shortfallHistorical one-day 95% VaR is the positive loss at the 5th-percentile daily return. ES is the average loss in that lower tail. Minimum 20 daily returns. These historical statistics do not bound future losses.
Beta / alphaDaily portfolio versus BTC returns. Beta = covariance / BTC variance; alpha = annualized daily excess intercept. Correlation is Pearson’s r. Tracking error is the annualized SD of daily return differences. Information ratio is their annualized mean/SD. Regression metrics need ≥20 aligned daily returns.
Profit factor / win rateDaily profit factor uses net equity gains divided by losses, including inventory effects. Daily win rate excludes flat days. Matched-cycle stats include completed adjacent pairs only; a 100% cycle win rate can coexist with a losing portfolio. ∞ means gains without observed losses; no observations show N/A.

Original model & reproducibility

The original mode preserves the v1 grid_trading_bot-inspired model: N price levels, a 50% BTC seed, midpoint filters and Q = initial balance / N / entry price. Its default end policy marks open holdings. A midpoint remains a chart reference in both modes; optional activation triggers are separate.

Prices are fetched directly from the BTC analytics dataset. Picker limits come from the loaded file. Naive timestamps are UTC, invalid records are counted, and gaps are reported. Default ranges use only the first selected close. Every bar affects accounting; only plotted lines may be reduced while preserving bucket extrema. JSON exports retain inputs, selected-data hash, definitions, results and the quant summary.

Close-only data cannot reconstruct ticks, candle extremes or liquidity. Binance rules are adapted for this research sandbox; this is not an exact replica of live exchange execution. The quant summary is generated deterministically from measured results, with no remote AI or trading connection.
